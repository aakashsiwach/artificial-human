# Biological blueprint

The human body is a design analogy for a modular software organism. The mapping is useful for boundaries and feedback loops, but each digital component remains ordinary software.

| Biological inspiration | Digital subsystem | Initial responsibility |
| --- | --- | --- |
| Brain | Brain | Goal decomposition and deliberation |
| DNA | Identity | Owner-authored values, preferences, constraints |
| Neurons | Nervous system | Typed internal events |
| Hippocampus | Memory | Consent-based storage and retrieval |
| Eyes and ears | Sensory system | Explicit, permission-scoped observations |
| Heart and vessels | Circulation | Prioritised internal work scheduling |
| Oxygen | Metabolism | Bounded resource budgets |
| White blood cells | Immune system | Detect abnormal signals and recommend defence |
| Stem cells | Regeneration | Propose isolated repair and replacement work |
| Sleep | Sleep system | Review and consolidate memory candidates |

## Immune cell roles

- **Sentinel / dendritic role:** collect evidence and classify unusual signals.
- **Neutrophil role:** recommend rapid containment for urgent incidents.
- **Macrophage role:** correlate evidence and prepare an incident history.
- **B-cell role:** maintain reviewed patterns and known remediations.
- **T-cell role:** challenge a proposed repair against policy and regression evidence.
- **Stem-cell role:** provision a fresh, isolated worker environment.

These are software roles, not biological agents. High-impact actions remain subject to explicit approval.

## Oxygen and circulation

The digital organism consumes compute, storage, network access, time, and model-provider budget. The resource governor currently tracks declared operation and token budgets; future host monitoring may add measured CPU, memory, and GPU telemetry. Background learning must not starve safety-critical work.

## Clone learning and memory

A personal model should be built from explicit, attributable data. Memory types are kept distinct:

- Episodic: an event and its context.
- Semantic: facts and concepts.
- Procedural: how a task is performed.
- Preference: confirmed likes, dislikes, and interaction choices.
- Decision: choices together with reasons and outcomes.
- Working: temporary context for an active task.

Inferred traits must be marked as hypotheses, not facts. The owner must be able to inspect, correct, export, and delete retained information.
